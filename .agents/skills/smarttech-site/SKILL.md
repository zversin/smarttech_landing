# SmartTech: актуальные цены и предложения

Работай самостоятельно и сообщай владельцу результат простым русским языком. Не перекладывай технические действия на пользователя, если доступны инструменты. Не называй старый прайс актуальным. Следуй подтверждённому правилу владельца: оборудование по публичной цене INTANT плюс его работы; итог округляется вверх. Маржу, прибыль, наценку и дополнительные финансовые сценарии не рассчитывай без отдельного запроса.

## Постоянный алгоритм владельца

**Подтянуть → проверить → округлить → обновить.**

1. Подтянуть свежий `main`, сохранив локальную работу.
2. Проверить точные модели и текущие публичные цены на intant.kz или в официальном XLSX; перепроверять доступ, даже если раньше был 403.
3. Прибавить действующие работы и материалы владельца, округлить общий итог вверх до 5 000 ₸. Не добавлять маржу и не выполнять дополнительные финансовые расчёты.
4. Обновить калькуляторы, карточки, RU/KZ/EN, WhatsApp и дату сверки; выполнить тесты, сборку и проверку в браузере. При поручении «залить/опубликовать» сделать обычный push в `main`, дождаться успешной сборки GitHub Pages нужного коммита и проверить реальные страницы smarttech.asia. Повторное подтверждение уже порученной публикации не требуется.

## Контекст и границы

- Репозиторий: `zversin/smarttech_landing`, основная ветка `main`. В этой облачной среде checkout находится в `/workspace/smarttech_landing`.
- Публичный сайт: `https://smarttech.asia/`, GitHub Pages. Публикация облачной среды и публикация сайта — разные действия.
- Используй существующий checkout. Облачная задача уже изолирована; не создавай Git worktree без прямого запроса пользователя.
- Сайт статический: Node.js 18+, npm, Python 3 для локальной раздачи. npm-зависимостей и backend сейчас нет. Сначала проверь актуальный README и package.json: устройство проекта может измениться.
- Не отправляй сообщения поставщику или клиентам, не оформляй заказы. Не отправляй тестовые заявки в WhatsApp.
- Владелец поручил актуализировать цены по INTANT, округлять их и синхронизировать калькуляторы и предложения. При запросе обновления выполняй это без дополнительных вопросов. Ставки монтажа, настройки, интеграции и материалов сохраняй. Push и публикацию выполняй при наличии соответствующего поручения в текущем диалоге; не спрашивай повторное разрешение на уже порученное действие.

## 1. Подтянуть актуальную версию

1. Прочитай применимые AGENTS.md, README и этот навык. Проверь `git status --short`, текущую ветку и локальные коммиты.
2. Выполни `git fetch origin main`. Запиши полный SHA и дату `origin/main`, сравни с HEAD. Используй встроенную HTTPS-аутентификацию Git; отсутствие GH_TOKEN само по себе не означает отсутствие доступа.
3. Если запрос включает обновление, нет изменений отслеживаемых файлов, непересекающиеся локальные файлы навыка сохранены и возможно fast-forward, выполни `git merge --ff-only origin/main` в существующей рабочей ветке. Не переключай молча пользовательскую ветку и не меняй origin. При локальных изменениях, расхождении истории или конфликте ничего не сбрасывай и не делай автоматический stash. Продолжи аудит последнего `origin/main` через `git show`, если это позволяет задача; объясни конкретное препятствие обновлению.
4. Для аудита SHA конфигурации должен соответствовать исследуемой версии. Не смешивай локальные данные старой версии с новой веткой.
5. Выполни существующие проверки, описанные ниже. После действий проверь diff; сохрани пользовательскую работу.

## 2. Проверить опубликованный сайт

Разделяй три состояния: локальный checkout, удалённый main, фактически опубликованный сайт.

- При доступном GitHub API проверь настройки Pages, ветку/путь публикации, последний deployment/build и его SHA/статус. Успешный Git fetch не подтверждает API-доступ или право публикации.
- Получи публичные страницы, sitemap и относящиеся к ценам JS/config-файлы. Сравни содержимое с файлами выбранного коммита, учитывая перенаправления и кэш. Проверь основные страницы с калькуляторами. Дата коммита и HTTP 200 сами по себе не подтверждают актуальность содержимого.
- `git push --dry-run` проверяет часть пути push, но не доказывает, что реальная запись пройдёт branch protection. Не создавай коммит, ветку или деплой ради проверки доступа. Фактический push допустим в рамках порученного изменения.
- Если сайт/API закрыты сетью, обозначь статус публикации как непроверенный. Не обходи ограничения и не выдавай блокировку прокси за поломку сайта. При наличии инструментов настроек среды сохрани точные необходимые дополнения к доменам, сохраняя прежние правила. Не проси токен, пока не проверена существующая аутентификация.

## 3. Собрать полный список цен

Ориентиры в текущем проекте (прочитай заново, не полагайся на этот список как на неизменный):

- `pricing/intant.mjs`: единый снимок цен, модели/SKU и дата подтверждения. `scripts/update-intant.py` обновляет только полный проверенный набор.
- `pricing/config.mjs`: комплекты камер, турникетов/терминалов и ЖК; округление и минимальная стоимость проекта.
- `videonablyudenie-dlya-etazha/config.mjs`: базовая цена этажа, HDD и доля квартиры; проверь согласованность с общим калькулятором.
- `pricing/calculator.mjs`, `pricing/translations.json`, шаблоны, тексты WhatsApp, SEO/JSON и HTML после сборки: все отображения и даты источников.
- `pricing/audit-*.json` и `pricing/anpr-review-*.json`: исторические свидетельства, ограничения совместимости и составов. Это не текущие котировки.
- README может отставать от кода. Фиксируй противоречия, а расчёты воспроизводи из актуальных функций и точного состава оборудования.

Для каждого комплекта восстанови BOM: точный артикул, модификацию, количество, необходимые блоки питания, крепления, кабель, лицензии и услуги. Дроби агрегированные суммы на позиции только при наличии подтверждённого состава. Не выдумывай BOM по итоговой сумме.

## 4. Сверить с INTANT

Основные источники:

- `https://intant.kz/` — карточки и каталог поставщика.
- Актуальная ссылка прайса из `PRICE_SOURCE` в `pricing/config.mjs`; на момент создания навыка файл находился на `bitrix.intant.kz/api/import/files/` и назывался `Прайс-лист INTANT.xlsx`.

Порядок работы:

1. Проверяй доступ заново при каждом запуске: прежний 403 не означает постоянную блокировку. 20.10.2026 доступ к каталогу и XLSX восстановился через штатную сеть облачной среды. Получи доступный официальный прайс и/или точные карточки товаров. Скачанный XLSX проверь как файл Excel, а не HTML-страницу ошибки. Сохраняй исходник и дату получения вне публикуемого сайта; анализируй таблицу с реальными заголовками и валютой.
2. Для каждой позиции зафиксируй модель/вариант, URL, время получения с часовым поясом, дату самого прайса при наличии, прежнюю и новую цену в ₸, наличие и условия НДС. Дата скачивания старого прайса не делает цены свежими.
3. Сопоставляй полный артикул, исполнение, объектив, цвет, ёмкость, комплектацию и единицу продажи. Похожая модель, цена «от» или комплект другой комплектации не заменяют точное совпадение.
4. Используй публичную цену INTANT как стоимость оборудования в клиентском предложении — это подтверждённое правило владельца. Не запрашивай закупочную скидку или целевую маржу и не добавляй скрытую наценку. Если владелец отдельно задаст иные условия, следуй им.
5. Не добавляй НДС повторно к цене с НДС. Сравнивай закупку и продажу на сопоставимой налоговой базе; статус НДС и возможность вычета не предполагай. При конфликте карточки и прайса покажи обе даты/цены и диапазон, не выбирай удобную цену молча.
6. Для непроверенных позиций оставь старую цену только как датированную оценку и отметь пробел. 403, отсутствие товара или цена «по запросу» не означают нулевую стоимость и не подтверждают отсутствие изменений.
7. Сверь прежнюю и новую цену оборудования; пересчитай итог комплекта с сохранением действующих ставок работ и материалов. Не выполняй дополнительных расчётов рентабельности.

Не присваивай ANPR цену прежнего карточного въезда: полный комплект и совместимость требуют отдельной оценки. Одна камера не равна готовой системе. Сохраняй статус «по запросу», пока не подтверждены состав, питание/PoE, лицензии, интеграция привода и безопасность, геометрия въезда, формат номеров и температурное исполнение для места установки.

## 5. Правило цены владельца

Подтверждено владельцем: маржа не задаётся. Оборудование оценивается по тем же публичным ценам, что на INTANT, сверху добавляются существующие суммы монтажных, настроечных, интеграционных работ и материалов. Дополнительные расчёты прибыли, маржи, налоговых сценариев, целевой цены и допустимых скидок не нужны.

- Обновляй точные цены оборудования по проверенному источнику. Не округляй каждую позицию отдельно, если это изменит опубликованную цену INTANT.
- Пересчитывай суммы оборудования по составу и количествам, сохраняя действующие ставки работ/материалов и правила количества.
- Итог: `оборудование INTANT + действующие работы + действующие материалы`, затем округление вверх по `roundPrice` проекта (сейчас шаг 5 000 ₸), с сохранением действующего минимального заказа (сейчас 115 000 ₸ для камер).
- Согласуй базовый комплект этажа `FLOOR_CCTV_PRICE`, HDD, общие калькуляторы и все клиентские предложения. Не оставляй на главной старую цену, если калькулятор уже пересчитан.
- Проверь агрегированные суммы ЖК: меняй их лишь на основании подтверждённого BOM, не подменяй общий состав одной похожей позицией.
- Не начисляй НДС повторно и не вводи новые комиссии, резервы или наценки.
- Если точная модель недоступна или цена не подтверждена, сохрани датированную старую оценку с явным статусом либо существующее «по запросу». Не выдавай частичное обновление за полное и не обнуляй отсутствующие цены.

## 6. Рекомендации, изменения и проверки

- Сравни одинаковые конфигурации: камеры 1–4 с HDD 0/2/4 ТБ; турникеты 1–5 проходов с Face ID на одной/двух сторонах; ЖК в разрешённом диапазоне квартир. Модели без цены оставь по запросу.
- При порученном обновлении меняй источники цен и связанные тексты/даты, затем запускай генератор. Не редактируй сгенерированный HTML вручную, сохрани установленную владельцем схему без дополнительной наценки. Не изменяй тестовые ожидания только ради зелёного результата.
- Из корня репозитория: `npm test`, `npm run build`, `npm run lint`. Для аудита без изменений достаточно `npm test` и `npm run lint` (он проверяет генерацию без записи). После изменений проверь diff и согласованность калькуляторов, переводов, WhatsApp и базовой цены этажа.
- Для HTTP-проверки запусти `python3 -m http.server 4173 --bind 127.0.0.1` в постоянной сессии, если подходящий сервер ещё не работает. Сверь маршруты sitemap и локальные ресурсы через внутренние запросы. Не выдавай localhost-ссылки за публичный сайт.
- Если поручена публикация: отправь только подготовленные изменения обычным push, проверь Pages deployment нужного SHA и затем содержимое smarttech.asia. Не применяй force push. При блокировке не заявляй, что сайт обновлён.

## Ежедневный запуск

В репозитории настроен `.github/workflows/update-prices.yml`: ежедневно 04:00 UTC / 09:00 Asia/Qyzylorda; доступен ручной workflow_dispatch. Он использует штатные ресурсы GitHub, встроенный токен и полный порядок владельца, включая публикацию и проверку smarttech.asia. Повторное подтверждение ежедневных обновлений не требуется: владелец поручил автоматический запуск.

Данные находятся в `pricing/intant.mjs`, отображение цен генерируется из `pricing/render.mjs`, шаблонов и `pricing/translations.json`. Не возвращай ручные копии цен в калькуляторы, переводы или тесты. `site-i18n.js` и HTML — результаты сборки. Ставки работ/материалов, минимальный заказ и шаг округления меняй только по отдельному запросу владельца.

Перед изменением автоматизации запускай Python unittest, npm test, build, lint и локальный HTTP/браузерный тест. Сбой источника не должен публиковать частичные данные. Если расписание/первый запуск не удалось подтвердить, явно сообщи оставшийся блокер вместо заявления, что автоматизация работает.
