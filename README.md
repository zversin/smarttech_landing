# SmartTech — smarttech.asia

Статический многостраничный сайт: HTML, CSS и JavaScript. Публикуется через GitHub Pages из ветки `main`, корень репозитория. Домен задан в `CNAME`. Фреймворков и npm-зависимостей нет.

## Структура сайта

| Адрес | Назначение |
| --- | --- |
| `/` | Основной лендинг: услуги, комплект на этаж, три комплекта СКУД с ценами, кейсы, этапы и контакты |
| `/videonablyudenie/` | Видеонаблюдение: обзор, запись, доступ и переход к комплекту на этаж |
| `/videonablyudenie-dlya-etazha/` | Отдельный лендинг для жильцов: комплект, условия, калькулятор, FAQ и форма |
| `/kontrol-dostupa/` | Турникеты и Face ID: START 3000/6000/10000, модернизация, условия и FAQ |
| `/ohrannaya-signalizaciya/` | Датчики, зоны контроля, сценарии и уведомления |
| `/integraciya-i-servis/` | Интеграции, перенос данных, отчёты и сопровождение |
| `/proekty/` | Полные кейсы КазУТБ, спортивного комплекса и общежития, реальные фото |
| `/o-kompanii/` | Подход компании, этапы работы и партнёры |
| `/kontakty/` | Телефон, WhatsApp, Instagram и сведения для расчёта |

Основной путь к заявке проходит на главной: предложение и цена → WhatsApp. Верхнее меню ведёт к блокам главной: услуги, комплекты и цены, проекты, этапы, контакты. Состав комплектов раскрывается на месте; детальные страницы и лендинг этажа остаются дополнительными. Подвал содержит полную навигацию по услугам.

Старые ссылки `/#modernization`, `/#faq`, `/#capabilities`, `/#partners`, `/#case-kazutb` ведут в новые разделы через `navigation.js`. Соответствия хранятся в `site.config.mjs`. `/#packages` открывает комплекты прямо на главной. Старые `/#features`, `/#projects`, `/#process`, `/#about`, `/#contact`, `/#hero` продолжают работать на главной. Без JavaScript доступны обычные ссылки в меню и подвале.

## Редактирование и сборка

Нужен Node.js 18+. Устанавливать npm-зависимости не требуется.

```bash
npm run build
npm run lint
python3 -m http.server 4173
```

Откройте `http://localhost:4173/`. После редактирования исходников выполняйте build, затем lint. Все сгенерированные HTML, `sitemap.xml` и `robots.txt` нужно включать в коммит: GitHub Pages раздаёт их непосредственно из репозитория.

### Где что хранится

- `site.config.mjs` — карта страниц, адреса, SEO для RU/KZ/EN, совместимость старых ссылок.
- `pricing/intant.mjs` — единый проверенный снимок публичных цен INTANT, точные артикулы и дата источника.
- `pricing/render.mjs`, `pricing/translations.json`, `templates/site-i18n.js` — цены и переводы для генерации HTML и `site-i18n.js`; сгенерированный файл вручную не редактировать.
- `templates/page.html` — общий документ основной группы страниц.
- `templates/partials/header.html`, `footer.html` — единственные исходники шапки и подвала для всех страниц.
- `templates/partials/photo-modal.html` — просмотр фотографий на странице проектов.
- `templates/pages/home.html`, `service.html` — структура главной и типовой услуги. Короткие карточки СКУД на главной собираются из `templates/sections/packages.html`, поэтому состав и цены не дублируются в исходниках.
- `templates/sections/` — исходные разделы: комплекты, модернизация, проекты, компания, партнёры, этапы, FAQ, контакты и карточки услуг. Общие блоки подключаются при сборке.
- `templates/cctv-floor.html` — исходник лендинга для этажа.
- `scripts/build.mjs` — статическая сборка всех страниц, карты сайта и robots.txt.
- `style.css` — существующий визуальный стиль и компоненты; `site-structure.css` — сетки, меню, хлебные крошки и многостраничная структура.
- `navigation.js` — общее меню, прокрутка, перенос старых якорей.
- `script.js` — существующие переводы, переключение языка, галереи и WhatsApp для услуг.
- `site-i18n.js` — новые переводы структуры и описаний услуг.
- `index.html` и HTML в каталогах страниц — **результат сборки, вручную не редактировать**.

Восемь основных страниц поддерживают RU/KZ/EN; лендинг для этажа остаётся русскоязычным. Метаданные переключаются по текущей странице, поэтому название главной не подменяется названием комплектов турникетов.

## Видеонаблюдение на этаж

### Цена

`FLOOR_CCTV_PRICE` в `videonablyudenie-dlya-etazha/config.mjs` вычисляется из общего калькулятора и снимка `pricing/intant.mjs`. После изменения снимка выполнить `npm run build`. Цена на главной, hero лендинга, сравнение, калькулятор, WhatsApp и SEO используют эту настройку. HTML содержит сгенерированные значения и читается без JavaScript.

### Калькулятор комплекта и архива

На странице этажа можно выбрать 1–4 камеры, вариант без HDD или HDD 2/4 ТБ, средний битрейт 1/2/4 Мбит/с на камеру и 2–8 квартир. `packagePrice()` и `archiveDays()` в конфиге используются для общей цены, доли с квартиры, срока хранения и сообщения WhatsApp. Базовая цена 2 камер с HDD 2 ТБ вычисляется через `cameraPrice(2, 2)` из единого снимка `pricing/intant.mjs`. Монтаж max(15 000 × камеры, 25 000), расходники 5 000 × камеры, настройка 30 000. Проект минимум 115 000 ₸; итог округляется вверх до 5 000 ₸. Без HDD нет локального архива.

Архив: ёмкость в десятичных байтах × 0.9 × 8 / (камеры × средний битрейт в бит/с × 86400). Для двух камер, 2 ТБ и 2 Мбит/с получается 41.67 суток; калькулятор округляет вниз до 41 дня. 10% — расчётный запас, фактический срок зависит от настроек и сцены. Расчёт предполагает непрерывную запись 24/7. Основная карточка и сравнение абонплаты сохраняют цену базового комплекта; результат калькулятора показан отдельно.

### Фото

Реальные фото кладутся в `public/images/cctv-floor/`. Имена и рекомендации: `public/images/cctv-floor/README.md`. Соответствия — `videonablyudenie-dlya-etazha/photos.mjs`. До добавления файлов отображаются подписанные заглушки без 404. После добавления фото нужна сборка.

### WhatsApp и форма

Номер: `77087262237`, как на исходном сайте. На страницах услуг сообщение содержит выбранную услугу; в комплектах контроля доступа — модель и цену; на лендинге этажа — описание предложения и стоимость.

Форма лендинга валидирует данные и открывает подготовленное сообщение с именем, телефоном, адресом, подъездом, этажом и количеством квартир. Пользователь отправляет его в WhatsApp самостоятельно. Backend и подтверждения доставки нет; интерфейс сообщает только о подготовленном сообщении. Номер лендинга настраивается через `WHATSAPP_NUMBER` в его конфиге.

### Аналитика

Новых счётчиков нет. При уже подключённом `gtag` или `dataLayer` лендинг отправляет `cctv_floor_whatsapp_click`, `cctv_floor_form_open`, `cctv_floor_form_submit`, `cctv_floor_calculator_change`. `form_submit` означает передачу сообщения в WhatsApp (`channel: whatsapp_handoff`), не доставку. Персональные данные в события не включаются.

## Проверки

`npm run lint` проверяет синтаксис JavaScript, актуальность сгенерированных файлов, JSON метаданных, один H1/main на страницу, уникальность title/id, canonical, внутренние ссылки между страницами, якоря, локальные картинки и srcset, совместимость старых адресов, цены, калькулятор и наличие всех страниц в sitemap.

При изменении структуры дополнительно проверьте в браузере: 375, 390, 430, 768, 1024 и 1440 px; RU/KZ/EN; мобильное меню; переходы главная → услуга → контакт; галерею проектов; калькулятор и форму этажа; старые ссылки на разделы. Для QA не отправляйте реальные сообщения в WhatsApp.

## Навигация и передача расчёта

На главной `/#calculators` доступны три калькулятора. Шапка и первый экран ведут к этому выбору. Кнопки «Открыть калькулятор» ведут к расчёту на сайте; кнопки WhatsApp явно называют внешнее действие. Ссылки из карточек СКУД передают выбранную модель через `?model=…#calculator`. В калькуляторах ЖК/СКУД есть необязательное поле города/объекта и предварительный текст сообщения; этот же текст передаётся в WhatsApp. В калькуляторе камер тоже показан текст сообщения. Сообщения не отправляются автоматически, персональные сведения из нового поля не сохраняются в localStorage.

Главная: единый блок `#features` с сохранённым входом `#calculators`. Основные направления — камеры, домофоны, турникеты; дополнительные — сигнализация и интеграция без калькуляторов. Пункт меню «Услуги и расчёт» ведёт к этому блоку.

## Работа с сайтом

Постоянный порядок: подтянуть свежий `main` → проверить цены INTANT → прибавить действующие работы и материалы и округлить итог вверх до 5 000 ₸ → обновить калькуляторы и предложения. Подробности и проверка публикации: [.agents/skills/smarttech-site/SKILL.md](.agents/skills/smarttech-site/SKILL.md).

## Ежедневное автоматическое обновление

Workflow [.github/workflows/update-prices.yml](.github/workflows/update-prices.yml) запускается каждый день в 09:00 Asia/Qyzylorda (04:00 UTC), а также вручную кнопкой Run workflow в GitHub Actions. Компьютер владельца не участвует.

Порядок: свежий `main` → официальный XLSX INTANT и карточка точного турникета → 18 точных позиций → существующие работы/материалы → округление вверх до 5 000 ₸ → тесты и генерация RU/KZ/EN, HTML и WhatsApp → commit в `main` → явный запрос сборки GitHub Pages → проверка публичных страниц и файлов цен на smarttech.asia. Дата успешной сверки сохраняется ежедневно, даже если суммы не изменились. Все проверки и изменения доступны в истории Actions и Git.

Установка пакетов для Python не требуется. Сеть, дата/валюта прайса, точные SKU и модели, положительные цены и полное покрытие проверяются до записи снимка. При неполном или неоднозначном источнике прежние цены сохраняются, workflow завершается ошибкой; уведомления зависят от настроек GitHub. Модели и полные системы со статусом «по запросу» не заменяются похожими товарами.

Локальный запуск:

```bash
python3 -m unittest discover -s scripts -p 'test_*.py' -v
python3 scripts/update-intant.py --force
npm test
npm run build
npm run lint
```

`--force` обновляет дату проверенного снимка, даже если цены не изменились. Без флага неизменный снимок не переписывается. Публикация — отдельный шаг после проверок. В Actions используется встроенный `GITHUB_TOKEN` с `contents: write` и `pages: write`; персональный токен не требуется. Явный запрос Pages необходим, потому что bot push со встроенным токеном сам по себе не запускает legacy Pages.

## Яндекс Метрика

Подключён счётчик SmartTech **113700627**. Номер публичного счётчика задаётся в `analytics.config.mjs` (`METRIKA_COUNTER_ID`). Пока он равен `null`, счётчик на сайт не добавляется. После задания номера выполнить build, тесты и lint. Счётчик работает только на smarttech.asia и www.smarttech.asia; локальные проверки не отправляют статистику.

Действия также записываются в параметры визитов: `smarttech_actions` (совершённые действия) и `smarttech_context` (калькулятор и выбранный комплект). Для этого отдельное создание целей не требуется; эти данные доступны в отчёте Метрики «Параметры визитов».

Для стандартного отчёта по конверсиям в аккаунте можно создать цели типа «JavaScript-событие» (само подключение сайта их не создаёт):

| Название | Идентификатор |
| --- | --- |
| Открыт калькулятор | `calculator_open` |
| Изменён расчёт | `calculator_change` |
| Нажат WhatsApp | `whatsapp_click` |
| Нажата кнопка звонка | `phone_click` |
| Форма передана в WhatsApp | `form_whatsapp_handoff` |

События отражают действия на сайте: клик WhatsApp и передача формы не подтверждают отправку сообщения или получение заявки, а клик телефона не подтверждает разговор. Сохраняются только тип калькулятора, допустимые варианты комплекта и место кнопки; имена, телефоны, адреса и содержимое сообщений не включаются в параметры событий. Автоматическая передача внешних ссылок отключена, поскольку ссылки WhatsApp могут содержать заполненный клиентом текст. Вебвизор не включён.

Для ссылок из Instagram и рекламы используйте UTM-метки. Реальные обращения сопоставляются с данными Метрики отдельно.
